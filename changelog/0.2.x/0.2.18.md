# 0.2.18 — 2026-09-19

## Added

- **Hosted endpoint** — `server.json` lists the public streamable-http remote at `https://libofcongress.caseyjhand.com/mcp`.

## Changed

- **Stateless session mode is explicit** — `createApp` now declares `sessionMode: 'stateless'`, so a source run with `MCP_SESSION_MODE` unset resolves stateless instead of `auto` (which resolved to stateful); an explicitly set `MCP_SESSION_MODE` still overrides it. The Docker image and `.env.example` already pinned `stateless`.
- **Argument-rejection envelope** — an invalid tool call now carries `structuredContent.error` (code `-32602`) with `data.reason: "invalid_arguments"` and a schema-derived `Recovery:` hint (mcp-ts-core [#377](https://github.com/cyanheads/mcp-ts-core/issues/377), [#445](https://github.com/cyanheads/mcp-ts-core/issues/445)); the error text closes with a `(reason … · not retryable)` suffix when the error carries a reason or retryable flag ([#458](https://github.com/cyanheads/mcp-ts-core/issues/458)).
- **Framework internals** — `/.well-known/mcp.json` publishes the resolved session mode under `_meta["io.github.cyanheads.mcp-ts-core/sessionMode"]` ([#387](https://github.com/cyanheads/mcp-ts-core/issues/387)); the Bun engines floor rises `>=1.3.0` → `>=1.4.0` and the skill tree moves `skills/` → `framework-skills/` ([#428](https://github.com/cyanheads/mcp-ts-core/issues/428)).

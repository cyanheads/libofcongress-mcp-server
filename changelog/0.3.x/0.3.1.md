# 0.3.1 — 2026-10-07

## Changed

- **`@cyanheads/mcp-ts-core` ^0.13.6 → ^0.13.13** — tool and resource error results carry `data.requestId`, and tool errors end `content[]` with `request <id>` (0.13.10); a declared `recovery` hint reaches every matching failure without per-call forwarding (0.13.10); stack traces and request context no longer reach client error data (0.13.7, 0.13.8), and neither does `data.rootCause` (0.13.13); `@modelcontextprotocol/server` 2.0.0 → 2.2.0 (0.13.9, 0.13.11).
- **Tool and resource handlers no longer spread `ctx.recoveryFor(...)`** — the framework fills each declared hint. The rate-limit paths keep the service's countdown hint, which overrides the static one. Client-visible output is unchanged.
- **Docker image installs production dependencies in a build-platform `deps` stage**, cross-installing for the target; `scripts/install-otel.ts` adds the OpenTelemetry peers and `scripts/prune-musl-packages.ts` removes musl-only packages. The image no longer sets `MCP_FORCE_CONSOLE_LOGGING` (nothing read it).
- **`.env.example` documents opt-in framework variables** — `MCP_REQUEST_STATE_KEY`, `MCP_HTTP_RESUMABILITY*`, `LOG_TOOL_FAILURE_PAYLOADS`, `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES`, `LOG_LLM_INTERACTIONS`, and the `OTEL_EXPORTER_OTLP_{TRACES,METRICS,LOGS}_ENDPOINT` overrides. Documentation only; the server gains no feature.
- **npm `files` excludes `dist/*.mcpb`**, so a bundle built before publishing stays out of the tarball.
- **Maintenance resync** — `framework-skills/`, `scripts/` (`lint:packaging` adds bundle-exclusion, manifest-version, Dockerfile-platform, and `server.json` launch-shape checks; `release:github -- --check` validates the tag), `CLAUDE.md`/`AGENTS.md`, `.gitignore`/`.dockerignore` (`.env*`), `.mcpbignore`, the CodeQL workflow (one analysis per language), and README tool descriptions.

## Fixed

- **`server.json` npm entries start the right transport** — the package bin ignores its arguments, so the `run start:*` arguments did nothing and the HTTP entry started stdio. The entries drop those arguments and use `runtimeHint: "npx"`, and the `streamable-http` entry sets `MCP_TRANSPORT_TYPE` to `"http"`.

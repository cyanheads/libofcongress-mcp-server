# 0.4.0 — 2026-10-14

## Changed

- **`libofcongress_search` renamed to `libofcongress_search_items`** ([#49](https://github.com/cyanheads/libofcongress-mcp-server/issues/49)), display title `Search LOC Items`. Inputs, outputs, and results are unchanged; there is no alias, so a call to the old name fails as an unknown tool. Callers switch the name.
- **www.loc.gov requests go through one queue** ([#50](https://github.com/cyanheads/libofcongress-mcp-server/issues/50)): concurrent calls start in arrival order at least `LOC_REQUEST_DELAY_MS` apart, and no 60-second window holds more than LOC's documented 20 starts, whatever the delay is set to. Retries re-queue, and the 1-hour block is checked again when a queued request is dispatched, so callers already waiting when a 429 lands fail without sending anything. id.loc.gov and the tile.loc.gov OCR fetch stay off the queue.
- **One 50-second budget per tool call** ([#52](https://github.com/cyanheads/libofcongress-mcp-server/issues/52)) replaces the 30-second per-request timeout and its four-attempt retry ladder (about 128 seconds). It covers queue wait, every attempt including its body read, backoff, and the newspaper page's OCR fetch. A timeout ends the call instead of re-sending the query; network faults still retry while budget remains, and 429, HTML soft-block, and 5xx still fail fast. An OCR fetch left without budget degrades as before (`ocr_available: true`, empty text).
- **`@cyanheads/mcp-ts-core` ^0.13.13 → ^0.13.15**: tool arguments that spell a number or boolean as a string, send a lone string for an array, or send `null` at an optional key are repaired before validation ([cyanheads/mcp-ts-core#707](https://github.com/cyanheads/mcp-ts-core/issues/707), [#602](https://github.com/cyanheads/mcp-ts-core/issues/602), [#616](https://github.com/cyanheads/mcp-ts-core/issues/616)), and a `-32602` argument rejection is bounded in size and CPU ([cyanheads/mcp-ts-core#648](https://github.com/cyanheads/mcp-ts-core/issues/648), [#710](https://github.com/cyanheads/mcp-ts-core/issues/710)).

## Added

- **`server_busy` failure reason** on `libofcongress_search_items`, `libofcongress_get_item`, `libofcongress_search_newspapers`, `libofcongress_get_newspaper_page`, `libofcongress_browse_collections`, and the `libofcongress://item/{+item_id}` resource: the queue cannot start the call within its budget. It is retryable and carries `retryAfter` seconds; it is never reported as `rate_limit_exceeded` (the 1-hour block).
- **`request_timed_out` failure reason** on those tools and resource and on `libofcongress_search_subjects`. The hints for `libofcongress_search_items` (format, subject, location, or date range), `libofcongress_search_newspapers` (date range, state, or newspaper title), and `libofcongress_browse_collections` (a more specific keyword) say how to narrow the request. The error names no upstream URL or host.

# 0.5.0 — 2026-10-14

## Added

- **`libofcongress_get_item` page list** ([#63](https://github.com/cyanheads/libofcongress-mcp-server/issues/63)): `resources[]` (URL, page count, `image`, `pdf`, `audio`) and a windowed `pages[]` (`page_url`, `has_text`) with `page_total` and `next_page_offset`. New inputs `page_offset`, `page_limit` (50 by default, 100 per call), and `include_files` for each listed page's download URLs. The item resource returns the first 50 pages.
- **`libofcongress_get_item` `subject_terms`** ([#57](https://github.com/cyanheads/libofcongress-mcp-server/issues/57)): the lowercase facet terms the `subject` filter accepts.
- **`libofcongress_search_items` `include_facets`** ([#57](https://github.com/cyanheads/libofcongress-mcp-server/issues/57)): adds `subject_facets` and `location_facets`, LOC's top 10 terms with item counts. Off by default, since the facet block slows every search.
- **`libofcongress_search_newspapers` day-level dates** ([#61](https://github.com/cyanheads/libofcongress-mcp-server/issues/61)): `date_start` / `date_end` take an integer year or a `YYYY`, `YYYY-MM`, or `YYYY-MM-DD` string. Dates are zero-padded before sending, and an impossible date fails as `invalid_date`.
- **`upstream_unavailable` failure reason** ([#55](https://github.com/cyanheads/libofcongress-mcp-server/issues/55)) on all six tools and the item resource: LOC unreachable, a 5xx or 403, an HTML page, or an empty or truncated body. The message names no URL, host, or transport text.
- **`invalid_item_id` failure reason** ([#66](https://github.com/cyanheads/libofcongress-mcp-server/issues/66)) on `libofcongress_get_item` and the item resource, raised before any request.

## Changed

- **`libofcongress_get_item` drops `resource_links`** ([#63](https://github.com/cyanheads/libofcongress-mcp-server/issues/63)) for the `resources[]` / `pages[]` lists above. A 582-page book went from 3,494 links to a 50-page window.
- **`libofcongress_get_item` `subject_headings` holds LCSH headings as cataloged** ([#57](https://github.com/cyanheads/libofcongress-mcp-server/issues/57)) (`Transportation--Oklahoma--Maps`); the facet terms it used to carry moved to `subject_terms`.
- **`subject` on `libofcongress_search_items` takes an LCSH heading or a facet term** ([#57](https://github.com/cyanheads/libofcongress-mcp-server/issues/57)). A heading splits at `--` into lowercase terms with dates dropped, ANDed, and a zero-result notice names them.
- **`date` on `libofcongress_search_items` and `libofcongress_get_item` is the cataloged value** ([#62](https://github.com/cyanheads/libofcongress-mcp-server/issues/62)) (`1936 Apr.`), not the `YYYY-01-01` sort key LOC pads onto photos.
- **`libofcongress_search_newspapers` `state` matches the state only** ([#59](https://github.com/cyanheads/libofcongress-mcp-server/issues/59)), by full name or postal code. City and county names now return nothing, and `washington` no longer returns D.C. papers (`district of columbia` does). `newspaper_title` is documented as the exact `newspaper_title` of a search result, and an empty result with it set says so.
- **`libofcongress_search_subjects` queries id.loc.gov `suggest2`** ([#58](https://github.com/cyanheads/libofcongress-mcp-server/issues/58)): base headings such as `World War, 1939-1945` and `Aerial photography` now surface, an exact match ranks first, and a partial word falls back to headings that begin with it.
- **`libofcongress_get_newspaper_page` reads book and manuscript pages** ([#64](https://github.com/cyanheads/libofcongress-mcp-server/issues/64)) from the page's own text service, and a body that cannot be read as text gets a notice instead of a retry hint. It also takes `http://` and bare `loc.gov` page URLs, `/seq-M/` paths, and Chronicling America page links ([#66](https://github.com/cyanheads/libofcongress-mcp-server/issues/66)); `libofcongress_get_item` reads a loc.gov item link as its ID.
- **A `limit` past the per-call cap is served at the cap** ([#53](https://github.com/cyanheads/libofcongress-mcp-server/issues/53)) instead of rejected, up to 1000: 100 results on the paged tools, 50 headings on `libofcongress_search_subjects`, with `effectiveLimit` and a notice.
- **Text output is safe to render** ([#65](https://github.com/cyanheads/libofcongress-mcp-server/issues/65)): HTML character references are decoded once on every upstream string, `item.rights` HTML becomes plain text, and OCR text renders in a fenced code block.

## Fixed

- **A one-sided date range no longer returns results outside the bound** ([#60](https://github.com/cyanheads/libofcongress-mcp-server/issues/60)). An open start is sent as `0000` and an open end as the current year on both search tools. A lone `date_start` after the current year fails as `invalid_date_range`.
- **A Cloudflare challenge or HTML page from www.loc.gov pauses requests for 60 seconds** ([#54](https://github.com/cyanheads/libofcongress-mcp-server/issues/54)). The call fails as `upstream_unavailable` with `retryAfter: 60`, and later and queued www.loc.gov calls fail without sending until the pause lifts.
- **The `libofcongress://item/{+item_id}` resource accepts only a valid LOC item ID** ([#66](https://github.com/cyanheads/libofcongress-mcp-server/issues/66)); anything else fails as `invalid_item_id` before a request is made.
